* one full-panel heatmap
* parent group containers laid out across the whole panel
* child tiles nested inside each parent group
* subtle group headers at the top edge of each parent area
* no vertical section list
* no page-like grouped scrolling
* no large black dead zones

   * parent groups = sectors

Core requirement:
Replace the grouped-mode visual layout only.

The grouped view should be a hierarchical treemap:

root
group A
child tile
child tile

The root-level groups should be placed by a treemap algorithm across the full available panel. Then each group’s children should be laid out inside that group’s rectangle.

Do not render grouped mode as:

* vertical stacked sections
* separate rows per group
* scrollable cards
* repeated independent treemaps stacked vertically

TradingView-style grouped design:

1. Entire grouped heatmap fills the same panel as ungrouped mode.
2. Each parent group has a thin header label along the top edge:

   * uppercase group name
   * small P/C value
   * small child count
   * optional chevron “›” if you want TradingView feel
3. The group header should sit inside or over the parent group rectangle.
4. Child tiles render inside the parent group area below/under the header.
5. Parent group boundaries should be visible but subtle.
6. Children keep the same green/red/gray color logic.
7. Parent group background should be very dark/transparent, not a big solid card color that fights the children.
8. Child tiles should remain square-ish.
9. Tiny child tiles should still become readable on zoom.
10. Tooltip and click behavior should still work.

Add or refactor only the grouped renderer.

Recommended helper:
renderHierarchicalHeatmap(groups)

Where each group has:

* key
* name
* aggregate call_premium
* aggregate put_premium
* aggregate net_premium
* aggregate premium_pcr
* children: leaf tiles
* groupSizeScore = sum(child.tileSizeScore)

Parent layout:
Run treemap over groups using groupSizeScore:

* root size = measuredWidth x measuredHeight
* group value = sum child tile size scores
* use squarify
* use small padding between groups

Child layout:
For each group rectangle:

* reserve small header height, for example 18–24px depending on group size
* run a nested treemap for children inside:
  x = group.x0 + innerPadding
  y = group.y0 + headerHeight
  width = groupWidth - innerPadding * 2
  height = groupHeight - headerHeight - innerPadding
* child value = existing tile size score
* use the same squarify/ratio settings as ungrouped mode

Important:
The parent group treemap and child treemap should both use measured panel dimensions. Do not use hardcoded heights or stacked containers.
