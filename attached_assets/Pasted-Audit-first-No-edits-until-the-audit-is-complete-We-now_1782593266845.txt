Audit first. No edits until the audit is complete.

We now have a normalized backend endpoint:

GET /api/predict/investor/intelligence

This endpoint is the preferred source for the Investor mode page. It returns:

* tracked_odds
* equity_signals
* diagnostics
* cache_age_seconds
* grouped driver markets
* watchlist-first ticker impacts
* canonical theme-universe fallback tickers

Goal:
Redesign the Prophetik / Prediction Markets page into a cleaner terminal-style intelligence page without removing signal.

Current problem:
The page has too many separate glasscard sections, duplicate/conflicting interpretations, odds are too small, and useful data is spread across too many panels. The goal is to consolidate the signal, not delete it.

Investor mode layout:

1. Macro Odds Board
   Use payload.tracked_odds.

Display as compact cards or a dense terminal table.

Show:

* label
* category
* large YES/NO odds
* 24h delta
* 7d delta
* volume/liquidity if present
* dashboard priority if useful

This should include Fed, recession, cuts/hikes, SPX/index daily, target milestones, tech/earnings odds, and other tracked families returned by backend.

2. Market-Moving Event Tape
   Use payload.equity_signals.

This should be the main section.

Render as a dense terminal-style table, not giant glasscards.

Columns:

* Event
* Odds
* 24h Δ
* 7d Δ
* Direction
* Sector / Theme Read
* Watchlist Hits
* Quality

Odds must be visually prominent: large, bold, easy to scan. The current small blue odds text is too weak.

Each event_family_key should appear only once.

3. Clickable Event Detail Drawer / Modal
   Clicking an event row opens a drawer or modal.

Show:

* event title
* event_family_key if useful in dev/debug only
* large YES/NO odds
* 1h / 24h / 7d deltas
* volume
* liquidity
* signal quality
* direction
* why_it_matters
* driver_markets table
* theme_impacts
* bullish_watchlist
* bearish_watchlist
* conditional_watchlist
* bullish_fallback
* bearish_fallback
* conflicts
* source links if present

Clearly label fallback tickers as “Theme Universe Fallback”, not user watchlist tickers.

4. Watchlist Impact Matrix
   Aggregate ticker_impacts across all equity_signals.

Three columns:

* Bullish
* Bearish
* Conditional

Prioritize watchlist tickers. Show sector/theme context next to each ticker when available.

Fallback tickers should be visually separated or secondary.

5. Sector / Theme Rotation Matrix
   Combine the old Sector Rotation Signals and Theme Clusters concepts.

Render as a compact matrix/table:

* sector
* theme
* direction
* driver/event count
* quality/confidence
* impacted tickers/watchlist hits

Do not render separate duplicate cards for the same event_family_key.

6. Raw Market Screener
   Keep the existing raw market screener, but collapse it by default under “Raw Markets”.

Power users can expand it.

Do not make this the main page experience.

7. Diagnostics
   If payload.diagnostics exists, render a dev-only collapsed Diagnostics panel.

Show key fields:

* ticker_impact_source
* hardcoded_sector_stocks_used
* watchlist_symbols_count
* watchlist_ticker_hits
* canonical_theme_fallback_hits
* unmapped_theme_impacts
* theme_universe_theme_count
* duplicate_markets_collapsed
* grouped_event_families
* cache_age_seconds
