PART 2 — SINGLE TICKER ADD UX
==================================================

When user adds a ticker manually:

1. Normalize symbol uppercase.
2. Immediately insert an optimistic row into the Watchlist table.
3. Mark hydration status:

hydration_status:
{
  quote: "pending",
  technical: "pending",
  fundamentals: "pending"
}

4. Call backend add endpoint using the correct body field:

canonical_ticker

5. Reconcile optimistic row with backend response.
6. Invalidate/refetch Watchlist query.
7. Start short hydration polling for that symbol.

Do not wait for fundamentals/technical hydration before showing the row.

No duplicate rows.

If backend rejects ticker:
- remove optimistic row or mark failed
- show calm error toast

==================================================

- real fields replace pending values

done
error

PART 4 — SHORT POLLING AFTER ADD
==================================================

After successful add:

- poll hydration status endpoint for the added symbol every 5 seconds
- stop when quote, technical, and fundamentals are done/error
- also stop after 2 minutes max
- invalidate/refetch Watchlist table after each meaningful status change
- invalidate ticker detail cache for that symbol

Do not poll forever.

If multiple tickers are hydrating, poll efficiently:
- either batch status if backend supports it
- or lightweight per-symbol polling with sensible limits
