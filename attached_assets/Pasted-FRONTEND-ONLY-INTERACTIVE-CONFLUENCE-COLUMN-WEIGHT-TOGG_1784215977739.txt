FRONTEND ONLY — INTERACTIVE CONFLUENCE COLUMN WEIGHT TOGGLE / ADJUSTED CCS

Frontend repo only.

Do not touch backend.
Do not change backend scoring.
Do not change actionability logic.
Do not change canonical Confluence data.
Do not create endpoints.
Do not add provider calls.
Do not change modal tabs.
Do not rewrite the table.

Goal:

Add an interactive local scoring lens to the Confluence table.

When the user clicks a score-bearing component column header, that column becomes disabled/dulled/gray, and the displayed CCS recalculates as if that component was removed from the core score and the remaining active components were re-normalized back to /100.

The user can disable and re-enable as many component categories as they want.

This is UI-only. It does not mutate backend data.

==================================================
CORE SCORE COMPONENTS
==================================================

Canonical core components:

Theme: 15
Stage: 15
Options: 18
Technical Setup: 8
Entry / Exit: 12
Catalyst: 12
Investment: 12
Valuation: 8
Core max: 100

Visible table component columns:

Theme      -> theme_alignment_points /15
Setup      -> technical_setup_points /8
Options    -> options_alignment_points /18
Entry      -> entry_exit_points /12
Catalyst   -> catalyst_alignment_points /12
Invest.    -> investment_alignment_points /12
Valuation  -> valuation_alignment_points /8

Important:

Stage /15 is part of the core score but is not currently a visible table column. Until a visible Stage column is added, Stage should remain always included in the adjusted score.

So default active max is:

Stage 15
+ Theme 15
+ Setup 8
+ Options 18
+ Entry 12
+ Catalyst 12
+ Investment 12
+ Valuation 8
= 100

If Catalyst is disabled:
active max = 88

If Catalyst + Investment are disabled:
active max = 76

If Setup + Options + Valuation are disabled:
active max = 100 - 8 - 18 - 8 = 66

==================================================
ADJUSTED SCORE FORMULA
==================================================

Create a frontend helper:

const CORE_COMPONENTS = {
  stage: { max: 15, alwaysOn: true },
  theme: { max: 15, columnKey: 'theme' },
  setup: { max: 8, columnKey: 'setup' },
  options: { max: 18, columnKey: 'options' },
  entry: { max: 12, columnKey: 'entry' },
  catalyst: { max: 12, columnKey: 'catalyst' },
  investment: { max: 12, columnKey: 'investment' },
  valuation: { max: 8, columnKey: 'valuation' },
}

For each row:

activeCorePoints =
  stage_points
  + every visible component point where component is not disabled

activeCoreMax =
  stage_max
  + every visible component max where component is not disabled

adjustedCoreScore =
  activeCoreMax > 0
    ? activeCorePoints / activeCoreMax * 100
    : null

Display adjustedCoreScore in the CCS column when any component is disabled.

If no components are disabled, display the canonical backend core score as normal.

Rounding:
- display one decimal
- preserve existing color logic if possible
- sorting should use adjustedCoreScore when adjusted mode is active

==================================================
BONUS HANDLING
==================================================

Do not reweight bonus into core.

Bonus remains separate:

Core /100
Bonus /25

If Bonus column is clicked/disabled:
- gray out Bonus column
- exclude bonus from displayed total/subline
- show +0.0 bonus or muted bonus
- do not alter adjusted core score

If implementing Bonus toggle is risky, leave Bonus non-toggleable for this pass and clearly report that only core components are toggleable.

Preferred:
Make Bonus toggleable separately as a display/total toggle, not part of core reweighting.

==================================================
UI BEHAVIOR
==================================================

For every toggleable score-bearing column header:

- clicking the column header toggles that component active/inactive
- inactive header becomes dull gray
- inactive column cells become dull gray / reduced opacity
- inactive column values remain visible but muted
- tooltip/title:
  "Excluded from adjusted CCS. Click to include."

Active tooltip:
  "Included in adjusted CCS. Click to exclude."

Add a small visual indicator in the header:

- active: normal label
- inactive: label with muted/disabled icon or "off" state

Add a small reset control near the Confluence table header:

"Reset weights"

Clicking Reset:
- re-enables all components
- restores canonical CCS display
- clears adjusted mode

Optional but preferred:
Persist disabled components in localStorage so the user’s view survives page refresh.

Key:
caelyn_confluence_disabled_components_v1

==================================================
SORTING BEHAVIOR
==================================================

Do not break existing column sorting.

If the table currently uses header click for sorting, avoid conflict.

Preferred behavior:

- clicking the column label/toggle chip toggles inclusion
- clicking the sort arrow sorts
- or add a small eye/weight toggle button inside the header

Do not make it impossible to sort.

CCS sorting:
- if no disabled components: sort by canonical CCS
- if any disabled components: sort by adjustedCoreScore

Component column sorting:
- still sort by that component’s raw points even if disabled
- disabled just affects adjusted CCS, not the column’s own sort value

==================================================
DISPLAY ADJUSTED MODE
==================================================

When any component is disabled, show a small banner/chip near table title:

"Adjusted CCS: excluding Catalyst, Investment"

or:

"Adjusted view active · 6/8 core components included"

In CCS cell:
- show adjusted score prominently
- show canonical score in small muted text if space allows:

Adjusted 74.2
Orig 68.9

or:

74.2 adj
68.9 orig

Do not overwrite backend canonical data.

==================================================
DO NOT CHANGE ACTIONABILITY
==================================================

Important:

Do not recalculate:

- Decision
- Ready / Near / Watch labels
- execution state
- bucket
- why_now
- why_wait

Those are backend canonical actionability outputs.

Only recalculate displayed CCS/ranking as a local adjusted score.

This avoids pretending the backend would make a different trade decision under the user’s temporary score lens.
