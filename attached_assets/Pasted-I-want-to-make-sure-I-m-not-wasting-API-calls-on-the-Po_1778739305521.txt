What each endpoint costs:

Endpoint	External API calls	Cache	When to call
GET /api/portfolio/holdings	None — pure JSON file read	No	Only needed to bootstrap a ticker list before the terminal loads
GET /api/caelyn-terminal	Tradier quotes + histories, CoinGecko, FMP fundamentals	5 min in-memory	Primary data load — already includes enriched holdings with prices

POST /api/portfolio/review	Gemini/Claude	None	User-triggered only
The two overlaps to watch for on your frontend:

/api/portfolio/holdings + /api/caelyn-terminal — if you call both on load, holdings is redundant. The terminal already returns the complete enriched holdings list. The only valid reason to call holdings first is to show a skeleton/ticker list while the slower terminal call is in-flight.

/api/portfolio/quotes + /api/caelyn-terminal — these both hit Tradier for equity quotes but use separate cache keys. If your frontend calls both within 5 minutes (e.g., calls the terminal on load and then hits quotes for a price refresh), the terminal's cached result means the second call costs nothing on the backend. But if both are called cold (e.g., after a restart), that's two Tradier requests for the same tickers.

The cleanest pattern is:

On load: call caelyn-terminal only (it already has live prices, no need for a separate quotes call)
On refresh/polling: call portfolio/quotes only (it's lightweight — just prices, no analytics rebuild)
portfolio/events and portfolio/options are fine as-is — they don't overlap with anything
