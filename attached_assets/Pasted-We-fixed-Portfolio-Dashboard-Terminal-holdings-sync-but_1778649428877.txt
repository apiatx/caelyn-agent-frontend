Required fix:
When FastAPI returns placeholder/empty data and the proxy injects local holdings, also build the derived Terminal fields from those holdings.

At minimum, populate:

1. Header / account totals
- total portfolio value
- daily P&L
- 1D / 5D / 1M / 6M / 1Y returns if available
- total return if cost basis exists

2. Holdings sidebar
Already working, but preserve:
- ticker
- current price
- daily change
- daily change %
- allocation %

3. Top movers
Calculate from holdings using daily change %:
- gainers = holdings with positive change %
- losers = holdings with negative change %
- sort by absolute move or positive/negative rank
- show top 2-4 as current UI expects

4. Asset allocation
Build from current holdings:
- If asset_type/category exists, group by it.
- Otherwise classify:
  - crypto if symbol is BTC/ETH/etc.
  - ETF if type says ETF
  - otherwise Individual Stocks
- Use market value weights.
- Must render even if all holdings are stocks.

5. Risk metrics
If historical data is unavailable, do not show fake precision.
But do compute what can be computed:
- top concentration = max holding allocation %
- top concentration symbol
- portfolio beta if beta values exist, weighted by allocation
- weighted volatility if historical/volatility data exists
- otherwise show unavailable state clearly without breaking panel

6. Volatility section
If per-symbol volatility exists from API or quote/historical helper, populate it.
If not available, show a clean unavailable state, not an empty broken panel.

7. Portfolio performance chart
This needs historical account value.
Current limitation:
The app only has current holdings + avg price, so it cannot accurately reconstruct portfolio value over time unless we add date_added / trade history / account snapshots.

For now:
- Do not fake a historical chart.
- If there is no historical portfolio series, show a clean empty state:
  "Performance history starts after portfolio tracking is enabled."
- But keep current total value visible.

8. Correlation matrix
If historical price series are available for the holdings, compute correlation.
If not, show a clean unavailable state:
  "Correlation requires historical price data."
Do not show old demo correlation.

Important:

4. Add account value snapshots
To track overall account value over time, add a lightweight snapshot system:
- On every portfolio save/edit/delete, record:
  - timestamp
  - total_account_value
  - holdings_count

- Also record once per page load or daily if not already recorded today.
- Store this in portfolio-value-history.json or the existing backend storage pattern.
- This series should feed the Terminal performance chart.

Avoid spam:
- Do not write a new snapshot on every render.
- Write on portfolio mutation.
- Optionally write once per day when portfolio is viewed.
