Chart Radar Fix Prompt — Preserve Existing Watchlist/MultiCharts Behavior

The Chart Radar page is not working correctly and the implementation may have drifted from the intended architecture.

Important: This feature must NOT make extra market-data API calls. Do not call FMP, Tradier, Polygon, Finnhub, TwelveData, or any other external data provider from this page. The only data request should be to our own backend/proxy endpoint that reads already-existing watchlist/portfolio data.

The goal is simple:

Use the existing Watchlist data that already powers the Watchlist page, group symbols exactly like the Watchlist page groups them, and display those symbols as TradingView chart widgets exactly like the existing MultiCharts page does.

Please stop adding new enrichment logic. This is a display/organization layer.

Core requirement:

* Chart Radar = Watchlist/Portfolio metadata + MultiCharts TradingView widgets.
* It should not fetch candles.
* It should not fetch quotes.
* It should not fetch fundamentals.
* It should not refetch market cap/theme/relative volume externally.
* It should not create new data sources.
* It should not hardcode demo symbols.
* It should not use fake fallback tickers.

Backend endpoint already exists:
GET /api/chart-radar/universe?source=watchlist&group_by=theme

This backend endpoint already returns the data from the watchlist/portfolio layer. Use it only.
