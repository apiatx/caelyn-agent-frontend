response.events

symbol / ticker

next_date

5. Separate issue:

Goal:

Fix only these two frontend issues:

A. Normalize Upcoming Earnings event fields so both old and new response shapes render correctly.
B. Fix GlobalPrefetch so it prefetches the actual Primary watchlist, not listData[0].

==================================================
PART 1 — NORMALIZE EARNINGS EVENT FIELDS
==================================================

In renderEarningsSection or the local helper used by Upcoming Earnings, create a normalization helper.

Example:

function normalizeEarningsEvent(ev: any) {
  return {
    ticker: String(ev.ticker ?? ev.symbol ?? "").toUpperCase(),
    company: ev.company ?? ev.company_name ?? ev.name ?? "",
    date: ev.next_date ?? ev.earnings_date_fmt ?? ev.earnings_date ?? ev.date_raw ?? null,
    rawDate: ev.date_raw ?? ev.earnings_date ?? ev.next_date ?? null,
    time: ev.time ?? ev.when ?? null,
    epsEstimate: ev.est_eps ?? ev.eps_estimate ?? null,
    lastEps: ev.last_eps ?? ev.previous_eps ?? null,
    revenueEstimate: ev.revenue_estimated ?? ev.revenue_estimate ?? null,
    revenueActual: ev.revenue_actual ?? null,
    importance: ev.importance ?? null,
    logo: ev.logo ?? null,
    marketCap: ev.market_cap ?? null,
    source: ev.source ?? null,
    lastUpdated: ev.last_updated ?? null,
  };
}

Then render from the normalized object.

Do not directly use `ev.next_date`, `ev.est_eps`, or `ev.revenue_estimated` in the UI without fallbacks.

==================================================

Current response may be:

{ events: [...] }

Use:

const rawEvents =

const events = rawEvents.map(normalizeEarningsEvent);

Render `events`.

Render at minimum:

- company if available
- date
- time if available
- EPS estimate if available
- revenue estimate if available

If date is missing, show “Date unavailable,” but still render the event.

Do not let missing logo/importance hide the event.

==================================================
PART 4 — FIX PRIMARY PREFETCH BUG
==================================================

In GlobalPrefetch, stop assuming:

listData[0] = Primary

That is false.

Current actual order:

listData[0] = Strong Bases
listData[1] = Primary

Find the actual Primary watchlist by stable identifier.

Preferred detection order:

const primary =
  listData.find(w => w.is_primary)
  ?? listData.find(w => w.kind === "primary")
  ?? listData.find(w => w.type === "primary")
  ?? listData.find(w => String(w.name ?? "").toLowerCase() === "primary")
  ?? listData.find(w => String(w.title ?? "").toLowerCase() === "primary");

Only if none exists, fall back to listData[0].

Then prefetch:

/api/watchlist/${primary.id}

Do not prefetch Strong Bases as Primary.

Add a dev-only console warning if Primary cannot be identified and fallback is used.
