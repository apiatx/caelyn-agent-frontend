============================================================
PROVEN REMAINING BUG
============================================================

The frontend Watchlist cache contains the RAW backend response:

  watchlist.analysis.sections[].tickers[]

Raw backend ticker rows commonly identify the ticker as:

  symbol

The frontend already knows this.

Current extractAllStocks() contains behavior equivalent to:

  ticker: t.symbol || t.ticker

Other Watchlist code also repeatedly uses:

  t.symbol || t.ticker

But the successful taxonomy-save React Query cache patch currently identifies
the target raw row using ONLY:

  (t.ticker || '').toUpperCase() !== upperTicker

This is wrong.

Example raw cached row:

  {
    symbol: "AXTI",
    primary_theme_id: null,
    ...
  }

Successful PUT:

  AXTI → packaging_substrates

Then setQueryData walks the raw sections and tests:

  t.ticker

t.ticker is undefined.

Therefore AXTI is never matched and never patched.

The PUT succeeds.
The database succeeds.
The frontend receives the authoritative response.
But the visible screener row continues to say:

  + Assign

until a later authoritative Watchlist GET replaces the row.

This is the remaining visible bug.

============================================================

  canonical_theme_id: savedPrimaryId ?? t.canonical_theme_id

  primary_theme_id
  canonical_theme_id

to represent the same current primary taxonomy identity.

Therefore the immediate client patch must not preserve an old
canonical_theme_id merely because the authoritative primary is null.
