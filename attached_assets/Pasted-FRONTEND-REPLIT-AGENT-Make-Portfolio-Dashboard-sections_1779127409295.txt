FRONTEND REPLIT AGENT — Make Portfolio Dashboard sections render instantly from aggregate holdings response

The Portfolio Dashboard tab is too slow.

Current user-visible bug:
- Fully Closed positions show first.
- Performance Scorecard and Partially Closed positions take forever or may never appear.
- The UI shows “No closed positions yet / Sell or trim a position...” where Partially Closed positions should be, even though Fully Closed positions below are already showing.
- This is wrong because backend now returns aggregate category lists directly from GET /api/portfolio/holdings.

Backend source of truth:
GET /api/portfolio/holdings returns:
- holdings
- open_positions
- partially_closed_positions
- fully_closed_positions
- option_open_positions
- option_partially_closed_positions
- option_fully_closed_positions
- option_closed_trades

Goal:
Render Portfolio Dashboard category sections immediately from GET /api/portfolio/holdings, without waiting on slower closed-trades grouping, terminal analytics, scorecard computations, or other derived queries.

Do NOT:
- change backend accounting logic
- re-infer categories from raw closed trades
- wait for /api/caelyn-terminal before rendering dashboard categories
- show “No closed positions yet” if partially_closed_positions or fully_closed_positions exist
- use stale localStorage category data
- hardcode tickers
- break CSV import flow
- break Portfolio Terminal
