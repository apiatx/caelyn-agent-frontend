PART 4 — FIX BASED ON THE ACTUAL FAILURE
==================================================

Case A — symbols = 0:
Fix selectedEarningsSymbols source.

For normal watchlists, do NOT use sortedTickers if it is empty at render time.
Use the active watchlist membership source that is actually loaded for the selected activeId.

Acceptable sources:
- watchlist?.tickers if populated
- watchlist?.csv_data mapped to ticker if that is actual membership
- cached same-watchlist response
- active watchlist metadata only if it includes tickers

For Favorites:
use Array.from(favoritesSet).

Do not run the query with [] and then render “No upcoming earnings” while the selected watchlist is still loading.

Case B — rawEvents > 0 but normalizedEvents = 0:
Fix normalization.

Support all observed event shapes:

ticker:
ev.ticker ?? ev.symbol

date:
ev.next_date ?? ev.earnings_date_fmt ?? ev.earnings_date ?? ev.date_raw ?? ev.date

company:
ev.company ?? ev.company_name ?? ev.name

eps estimate:
ev.est_eps ?? ev.eps_estimate ?? ev.epsEstimated ?? ev.eps

revenue estimate:
ev.revenue_estimated ?? ev.revenue_estimate ?? ev.revenueEstimated ?? ev.revenue

Case C — normalizedEvents > 0 but UI still shows “No upcoming earnings”:
Fix render guard ordering.

Correct order:

1. If selected symbols are still loading:
   show "Loading upcoming earnings…"

2. Else if selected symbols are truly empty:
   show "No tickers in this watchlist."

3. Else if query is loading:
   show "Loading upcoming earnings…"

4. Else if normalizedEvents.length > 0:
   render events

5. Else:
   show "No upcoming earnings for this watchlist."

The event rendering branch must come before final empty state.

Case D — two different Upcoming Earnings sections exist:
Remove or disable the stale old section.
Make the visible section use the new query data.

Case E — query cache has stale empty result:
Make query key include:
- selectedTabKind
- selectedTabId
- selectedEarningsSymbols.join(",")

Also ensure empty-symbol query never runs.

Case F — CSS/layout invisibility:
Render a plain visible list first to prove data:
- ticker
- date
- eps
Then restyle after visible.
