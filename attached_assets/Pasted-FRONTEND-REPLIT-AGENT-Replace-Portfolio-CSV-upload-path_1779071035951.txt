FRONTEND REPLIT AGENT — Replace Portfolio CSV upload path with new ledger import endpoint

Backend built the correct portfolio transaction ledger engine.

Old endpoint:
POST /api/portfolio/upload-csv

New endpoint:
POST /api/portfolio/transactions/import-csv

The old endpoint is wrong for brokerage transaction accounting because it aggregates buys/sells per ticker instead of replaying the full time-ordered ledger. It caused bugs like:
- SIVEF showing as fully closed even though it is still open.
- OUST and ALMU showing as partially closed even though they have not been sold.
- stale bad closed-trade records surviving after bad imports.

Frontend task:
Update the Portfolio Dashboard CSV upload flow so it ONLY uses the new ledger endpoint and never uses the old upload path again.

Do NOT:
- call /api/portfolio/upload-csv anywhere
- keep a fallback to the old endpoint
- parse/sort/classify brokerage transactions in frontend
- hardcode ticker fixes for SIVEF, OUST, ALMU
- create local-only portfolio state
- preserve stale closed-trade records after a full replace import
- break Watchlist CSV upload; this change is Portfolio CSV upload only

Audit first:
1. Locate Portfolio Dashboard CSV upload UI.
2. Locate every frontend call to:
   - /api/portfolio/upload-csv
   - upload-csv
   - portfolio CSV import/upload
3. Confirm whether there is an Express route/proxy for the old endpoint.
4. Replace all Portfolio CSV upload calls with:
   POST /api/portfolio/transactions/import-csv
5. Delete or disable any frontend/Express route that proxies /api/portfolio/upload-csv for Portfolio.
6. Keep Watchlist CSV upload untouched.

New request payload:
Send:

{
  "csv_data": "<raw CSV text>",
  "full_replace": true
}

Optional validation mode:
For dev/testing only, support:
{
  "csv_data": "<raw CSV text>",
  "full_replace": true,
  "validate": true
}

Important:
Default Portfolio CSV import should use full_replace=true unless there is already a deliberate append mode UI. The purpose is to rebuild the portfolio from the uploaded transaction ledger and prevent stale bad records from old imports.

Multiple CSV uploads:
The user needs to upload multiple brokerage transaction CSVs.

If the backend endpoint currently accepts one CSV string:
- Update the UI to accept multiple files.
- Read each CSV file as text.
- Combine them into one CSV import safely OR call the endpoint in a way backend supports.
- Best option if backend supports only csv_data string:
  - concatenate all rows after normalizing headers only if headers match
  - or send one combined csv_data string with all transaction rows
- Preserve source filenames if backend supports them. If not, do not invent fragile client accounting.
- If headers differ across files, show a clear error or send files one-by-one only if backend dedupe/full_replace behavior is safe.
- Ask backend only if the endpoint cannot support multiple files cleanly.
