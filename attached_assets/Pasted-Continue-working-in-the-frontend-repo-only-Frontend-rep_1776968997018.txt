Fix the Home `Unusual Options Flows` section and the main `Options Flow` page so the UI never misleadingly says "No unusual options activity detected" when the real situation is:

* refresh in progress
* stale snapshot available
* cache warming
* background scan still running

1. Home Unusual Options Flows
2. Options Flow page
3. empty/loading/error/status states for options data

* what exact payload fields currently drive the empty state
* whether the frontend treats cold/warming/refreshing the same as true zero-results
* whether stale snapshot metadata is already available but ignored
* whether the UI could display last-updated/source/refreshing state more honestly

IMPLEMENT
Assume backend will provide snapshot metadata or already does.

Required UI behavior:
A. Home Unusual Options Flows

* if results exist, always render them
* if results are stale but valid, still render them
* if refresh is in progress, show a subtle “refreshing” indicator, not an empty state
* only show “No unusual options activity detected” if backend explicitly indicates a completed scan with zero valid results
* if there is literally no snapshot yet, show a distinct warmup state like:

  * “Warming live options scanner…”
    not “no unusual activity”

B. Options Flow page

* same state distinction:

  * warming
  * refreshing
  * stale but available

* updated_at

* stale
* result_count

D. No new fetches / no polling hacks

* do not add timers or polling loops unless there is already an existing query refetch policy that just needs a small adjustment
* do not bypass the normal data flow
