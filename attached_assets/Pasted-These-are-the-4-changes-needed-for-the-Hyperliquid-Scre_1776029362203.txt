Fix 2 — Sections must never disappear during reload
What to do:

The screener currently clears the signal section content whenever it fetches fresh data, causing a blank flash.

Fix: always keep the last successfully fetched data visible while a reload is in progress. Show a subtle loading indicator (e.g. a small spinner or "Refreshing…" badge next to the timestamp) rather than blanking the content.

Implementation pattern:

// On refresh start — do NOT clear state
setLoading(true);   // show spinner
// ... fetch new data ...
// On success — replace data with new data
setData(freshData);
setLoading(false);
// On error — keep old data visible, show error badge
setLoading(false);
setError("Could not refresh. Showing last data.");

The section tables/cards should always have data if at least one successful fetch has completed.

Fix 4 — Fix the funding rate display (decimal point off)
What to do:

The backend previously sent funding as the raw hourly rate (e.g. 0.000935). Multiplying by 100 gave the hourly percentage (0.0935%/hr), which is ~8× too small — Hyperliquid displays the 8-hour funding rate.

The backend now sends a new field called funding8hPct in both the /api/hyperliquid/screener/snapshot and /api/hyperliquid/screener/sections responses.

funding8hPct is already the 8-hour funding rate expressed as a percentage. Display it directly with a % suffix.

Example values:

BRENTOIL: funding8hPct = 0.8061 → display as +0.81%
USOIL: funding8hPct = 0.7978 → display as +0.80%
Negative: funding8hPct = -0.094 → display as -0.09%
Replacement rules:

Anywhere you currently display (funding * 100).toFixed(4) + "%" → replace with funding8hPct.toFixed(4) + "%"
Anywhere you currently display funding * 100 → replace with funding8hPct
Use green colour for positive values, red for negative
Format to 4 decimal places for the section tables (e.g. +0.8061%) and 2 decimal places for summary cards (e.g. +0.81%)
The fundingAnnPct field (already sent previously) is the annualized funding rate as a percentage and is still correct — use it for the "ann." / annualized display in detail views (e.g. +105.2% ann.).

That's all 4 fixes. The backend changes (Fix 4) are already deployed. Fixes 1–3 are pure frontend changes.
