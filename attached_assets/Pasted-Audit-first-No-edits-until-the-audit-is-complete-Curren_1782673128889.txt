Critical rendering rules:

A. Never show an odds number without contract context.

Bad:
NVDA Price Milestone — 91.5%

Good:
NVDA Price Milestone
91.5% · NVIDIA above $X by DATE
[raw Polymarket question if target/date parsing is not available]

If display_subtitle is generic, such as only “NVIDIA”, “Tesla”, “Apple”, “Yes”, or a ticker/name, fall back to question.

Use this priority for context text:

1. question, if it contains useful contract terms like above/below/by/date/price/meeting/cuts/hikes
2. display_subtitle
3. event_title
4. label

B. Outcome summaries must be vertical lists.

Replace inline outcome_summary text with a compact OutcomeList component.

For outcomes[] render:

* one outcome per row
* label on the left
* probability on the right
* selected/priced outcome highlighted
* max visible outcomes in compact cards: 4
* “+N more” or “Show all” if more than 4
* full list in the detail drawer

Example:
Outcomes:
No change                  81.5%
25 bps increase            16.2%
25 bps decrease             1.2%
50+ bps increase            0.4%
50+ bps decrease            0.4%

Do not render this as one long inline sentence.

C. Command Center cards

Each category card item must show:

* display_title or label
* large priced_probability / yes_probability
* priced_outcome_label
* contract context line using question if useful
* compact vertical outcome list if outcomes[] exists
* 24h / 7d delta
* market_read

For Top Movers:
Do not show only:
Israel / Gaza / Hamas +67.5pp

Show:
Israel / Gaza / Hamas
+67.5pp 24h
[priced_outcome_label] · [question or useful contract subtitle]
Current odds: XX%

D. Event Impact Ledger

Event / Contract column should show:

* display_title or label
* useful contract context underneath, preferably raw question
* contract_context/end_date badge if available

Odds column should show:

* probability
* priced_outcome_label
  not just YES when YES is ambiguous.

If priced_outcome_label is generic, show question/subtitle directly below.

E. Detail drawer

Show:

* full question
* event_title
* display_title
* priced outcome
* full vertical outcomes[] list
* end date
* Polymarket URL
* market_read
* exposure

If outcomes[] exists, use it.
If outcomes[] is missing but outcome_summary exists, split it into vertical display rows if possible.
If both missing, show question and priced_outcome_label.

Never hide rows because metadata is incomplete.
