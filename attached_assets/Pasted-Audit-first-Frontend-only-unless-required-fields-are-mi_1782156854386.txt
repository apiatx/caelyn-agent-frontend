Audit first. Frontend-only unless required fields are missing from the already-loaded Watchlist payload. Do not touch backend. Do not add API/provider calls. Do not use an LLM.

Goal:
Add a filter/settings button to the Watchlist page `Screener` section.

The Screener section currently has two modes:

* Technical
* Fundamental

Add a compact filter/settings button in the Screener header that opens a popup/modal where the user can create filters across both Technical and Fundamental fields.

The same active filters must apply to both Screener modes.

Example:
User sets:

* VolX > 1.5x
* P/S < 4
* Revenue Growth > 50%

Then:

* Technical mode should show only tickers matching all active filters.
* Fundamental mode should show the exact same filtered ticker universe, just with fundamental columns displayed.

Core requirement:
The filters should operate on one unified Watchlist Screener row model, not separately on Technical and Fundamental tables.

Scope:
Only update the Watchlist page Screener section.

Do not change:

* backend
* provider calls
* Watchlist saved data
* Live News
* bottom tabs
* Golden Zone
* Growth Momentum
* HC Investment Zone
* HC Trade Zone
* Fundamental Grouping
* Theme Grouping
* Market Cap Grouping
* StockDetailModal
* Add ticker behavior
* Hide Foreign behavior, except it should combine correctly with filters

No new data fetching:
Do not call:

* FMP
* Tradier
* options endpoints
* analyst endpoints
* backend refresh endpoints
* LLMs

Use only the already-loaded Watchlist row data, technical fields, live quote fields, options fields, and CSV/fundamental merged fields.

Architecture:
Create a shared filtered Screener row set.

Suggested flow:

1. Build unified Screener rows from the same merged data already used by:

   * Technical Screener
   * Fundamental Screener

2. Apply active saved watchlist scope.

3. Apply Hide Foreign if enabled.

4. Apply Screener filters.

5. Feed the filtered symbol set into both:

   * Technical table
   * Fundamental table

Important:
Do not let Technical and Fundamental modes independently filter their own row arrays in ways that drift.

Preferred model:

* `allScreenerRows`
* `activeScreenerFilters`
* `filteredScreenerRows`
* `filteredSymbolSet`

Then:

* Technical mode renders technical rows where symbol is in `filteredSymbolSet`
* Fundamental mode renders fundamental rows where symbol is in `filteredSymbolSet`

This guarantees both modes show the same stocks.

Filter button:
Add a compact button in the Screener header near the Technical/Fundamental toggle.

Suggested label/icon:

* `Filters`
* or small sliders/settings icon
* show active count if filters exist: `Filters (3)`

When active filters exist, visually highlight the button.

Filter modal/popup:
Open a modal/popover with:

* title: `Screener Filters`
* list of available fields grouped by category
* ability to add/remove filters
* `Apply`
* `Clear All`
* `Close`

Clear All:
User must be able to clear all active filters with one click.

Clear All should:

* remove all custom filters
* reset the filtered Screener back to the active watchlist / Hide Foreign state
* update both Technical and Fundamental modes immediately

Filter behavior:
Default combine mode should be AND.

Meaning:
A row must pass every active filter.

Do not add OR logic in this pass unless simple and already supported. Keep it clean.

Supported filter types:

Numeric filters:
Operators:

* greater than
* greater than or equal
* less than
* less than or equal
* equals
* between

Text/category filters:
Operators:

* contains
* equals
* does not contain

Boolean/presence filters:
Operators:

* exists
* missing

Parsing:
Create robust parsing helpers.

Numeric values may appear as:

* `1.5x`
* `+50%`
* `$4.2B`
* `$850M`
* `1,250,000`
* `—`
* null
* undefined

Helpers:

* parseNumberLike(value)
* parsePercentLike(value)
* parseCurrencyLike(value)
* parseMultipleLike(value)
* getFilterFieldValue(row, fieldKey)

Rules:

* `—`, null, undefined, empty string = missing
* 0 is valid
* percentages should compare as percentage points, so `50%` parses to `50`
* VolX `1.5x` parses to `1.5`
* Market cap/revenue `$4.2B` parses to `4200000000`

Filter examples:

* VolX > 1.5
* P/S < 4
* Revenue Growth (Q) > 50
* Market Cap between 1000000000 and 10000000000
* Stage equals S2 Breakout
* Theme contains Semiconductor
* Options Score >= 50
* FCF Margin > 0

When filters are active, show compact chips in the Screener header or just below it.

Examples:

* `VolX > 1.5x`
* `P/S < 4`
* `Rev Growth (Q) > 50%`

Each chip should have an `x` to remove that individual filter.

Also show:

* `Clear All`

Counts:
Update Screener count text to reflect filtering.

Example:
`302 total · 248 shown · 12 filtered`

Or:
`302 total · 12 shown after filters`

Make it clear when filters are active.

Hide Foreign interaction:
Hide Foreign should combine with custom filters.

Example:

* first exclude foreign tickers
* then apply filters
* count shown should reflect both

Do not let Clear All turn off Hide Foreign unless user expects Clear All to clear only custom filters.

Preferred:

* Clear All clears only custom filters
* Hide Foreign remains controlled by its own button

Sorting:
Existing Technical and Fundamental table sorting should continue to work after filters are applied.

Apply filters first, then sorting.
