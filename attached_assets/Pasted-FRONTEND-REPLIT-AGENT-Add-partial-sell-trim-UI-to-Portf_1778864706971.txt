FRONTEND REPLIT AGENT — Add partial sell / trim UI to Portfolio Dashboard

Backend is ready.

New backend endpoint:
POST /api/portfolio/holdings/{ticker}/sell

It supports:
- sell_type: "shares"
- sell_type: "dollars"
- sell_type: "percent"
- sell_type: "full"

Backend uses average-cost accounting and returns the source-of-truth math.

Do not calculate final accounting only in frontend.
Do not bypass the backend sell endpoint.
Do not remove the full active holding when user only trims.
Do not create local-only closed trades.
Do not break current add/edit holdings, closed positions, or Portfolio Terminal.

Goal:
Update Portfolio Dashboard so users can:
1. Sell/trim a specific number of shares.
2. Sell/trim a specific dollar amount.
3. Sell/trim a percentage.
4. Close the full position.
5. Keep remaining shares active after partial sell.
6. See the sold portion in Closed Positions.
7. Have Terminal update immediately with remaining active shares only.

Current backend behavior:
- Selling by shares:
  - exact shares_sold
  - oversell returns 400
- Selling by dollars:
  - shares_sold = dollar_amount / exit_price
  - capped at current shares only for floating-point safety
- Selling by percent:
  - shares_sold = current_shares * percent_sold / 100
- Full:
  - sells all current shares
- Remaining active holding keeps same avg_cost under average-cost accounting.
- Closed trade records sold portion only.
- Response includes:
  - success
  - ticker
  - sell_type
  - shares_before
  - shares_sold
  - shares_remaining
  - exit_price
  - exit_value
  - cost_basis_sold
  - realized_pnl
  - realized_pnl_pct
  - closed_trade
  - active_holding or null
  - active_count
  - holdings_signature
  - cost_method

UI changes:
1. Replace/enhance the current Delete/Close button on active holdings.
2. Open a “Sell / Close Position” modal.
3. Modal should show:
   - ticker

   - current/last price if available

   - exit_price, default current/last price if available

   - optional close_reason/notes if existing pattern supports it
