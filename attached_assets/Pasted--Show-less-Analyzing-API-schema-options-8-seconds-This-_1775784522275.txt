Here's what I found and fixed:

Root cause: The TaoApp /current and /fear_greed API endpoints were intermittently failing (roughly every other refresh cycle — about every 10 minutes). When they failed, the code silently wrote price=0, block=0, fear_greed=0 to the cache, overwriting the last good data. The frontend saw zeros and showed the "Failed to load Bittensor data" error.

Fix: Implemented stale-on-error across all four data components. Now when any TaoApp endpoint fails transiently, the previous cached values are preserved rather than overwritten with zeros. The dashboard will continue showing the last known good data (at most 5 minutes stale) rather than crashing to zeros on a partial network hiccup.

Specifically:

tao_price / block_number: preserved from previous cache if /current fails
total_market (fear/greed): preserved from previous cache if /fear_greed fails
network_stats: preserved from previous cache if TaoStats stats endpoint fails
subnets: preserved from previous cache if the screener endpoint fails
To get this fix into production, you'll want to re-deploy.
