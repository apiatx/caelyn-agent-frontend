FRONTEND AGENT — Fix Themes mode parity with Sectors mode on Sectors page

- Sectors mode uses the correct toggle styling, badge text, columns, sortable headers, score bar, trend sparkline, and status layout.
- Themes mode has different spacing/styling, different columns, different sortable columns, no trend sparkline column, and the table feels like a separate component.

Goal:
Themes mode should use the exact same table shell/component/styling/interaction model as Sectors mode.

Do not redesign the page.
Do not change backend unless absolutely necessary.
Do not change Sectors mode.
Make Themes mode look like the same component with different data.

8. Data normalization function
Add a small frontend adapter, something like:

function normalizeThemeToSectorRow(theme) {
  return {
    rank: theme.momentum_rank,
    ticker: theme.leader_symbol || theme.symbols?.[0] || theme.id,
    sector: theme.label,
    price: theme.price ?? theme.leader_price ?? null,
    oneDay: theme.performance?.["1d"],
    sevenDay: theme.performance?.["7d"] ?? theme.performance?.["5d"],
    thirtyDay: theme.performance?.["30d"] ?? theme.performance?.["1m"],
    ytd: theme.performance?.["ytd"],
    oneYear: theme.performance?.["1y"],
    score: theme.relative_strength_score,
    trend: theme.trend ?? theme.sparkline ?? theme.history ?? null,
    status: normalizeThemeStatus(theme.trend_state ?? theme.rotation_state),
    raw: theme
  };
}

Then pass normalized theme rows into the same table renderer used by sectors.
