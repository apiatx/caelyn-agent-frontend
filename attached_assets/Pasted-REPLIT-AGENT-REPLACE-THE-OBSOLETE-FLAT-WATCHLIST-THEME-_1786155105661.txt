────────────────────────────────────────────────────────────
CANONICAL PRODUCT MODEL
────────────────────────────────────────────────────────────

The intended stock taxonomy UI is:

ONE ACTUAL ECONOMIC SECTOR
+
ONE PRIMARY THEMATIC MEMBERSHIP
+
ZERO OR MORE ADDITIONAL THEMATIC MEMBERSHIPS

The primary thematic membership can be either:

classification="theme"

OR

classification="sub_theme"

When the primary is a sub_theme, its parent Theme is derived through:

parent_theme_id

Do NOT redundantly store both parent Theme + child Subtheme as primary.

Example:

Sector:
Technology

Primary hierarchy:
Semiconductors
→ Foundry & Manufacturing

Stored primary_theme_id:

foundry_manufacturing

NOT:

semiconductors + foundry_manufacturing as two primary memberships.

The parent Theme is derived.

────────────────────────────────────────────────────────────
BACKEND CONTRACT — ALREADY IMPLEMENTED
────────────────────────────────────────────────────────────

Do NOT invent another backend endpoint.

The canonical atomic endpoint already exists:

PUT /api/themes/admin/ticker-taxonomy/{ticker}

Body:

{
  "primary_theme_id": "<theme or sub_theme id> | null",
  "additional_theme_ids": ["<theme or sub_theme id>", ...],
  "note": optional,
  "created_by": optional
}

The backend already:

- authenticates admin
- validates IDs
- rejects sector IDs as thematic memberships
- rejects market_lens
- rejects deprecated
- rejects non-assignable nodes
- permits theme or sub_theme
- removes primary from additional
- deduplicates
- prunes redundant ancestor memberships
- computes membership additions/removals
- writes primary + all membership changes in ONE Neon transaction
- invalidates taxonomy caches once
- rereads authoritative state
- verifies persisted state
- returns authoritative:

  primary_theme_id
  additional_theme_ids
  theme_ids
  subtheme_ids
  sector_id

Use this endpoint.

Do NOT sequence several POST calls from frontend.

Do NOT use:

POST /api/themes/admin/assign-primary-theme

for the new editor's Save action.

That is the old single-primary compatibility path.
