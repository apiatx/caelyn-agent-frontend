A newly fetched canonical Watchlist row must NEVER be discarded just because
the 10-field whitelist happens to match.

Replace this architecture.

Preferred safe model:

For each symbol cache the actual merge INPUT identities:

canonicalBaseRow
realtimeQuoteInput
normalizedOptionsInput
betaInput
outputRow

Reuse outputRow only when ALL corresponding inputs are unchanged.

Conceptually:

prev.base === baseRow
AND prev.quote === stableQuote
AND prev.options === stableOptions
AND Object.is(prev.beta, beta)

→ reuse prev.output

Otherwise:
→ build a new merged output row

Critical invariant:

A new canonical base Watchlist row reference MUST force a new output row,
therefore all technical/fundamental/taxonomy/history fields propagate.

Do not use a manually maintained whole-row display-field whitelist.

If realtime quote objects themselves receive new references on every poll even
when values are identical, stabilize them safely.

A quote may be reused only if every field consumed by mergeRealtimeQuote is
unchanged:

price

source
is_realtime
is_live_backup
is_stale
updated_at
quote_timestamp
staleness_seconds
market_session

Prefer a shallow canonical comparison local to Watchlist unless changing
useRealtimeQuotes globally is clearly safe for every consumer.

No stale quote metadata may be hidden.

Likewise normalize options data outside the realtime quote loop so unchanged
options inputs do not create a new object on every quote update.

PERFORMANCE FIX 1 — DO NOT MOUNT HIDDEN CONFLUENCE ON INITIAL LOAD
────────────────────────────────────────────────────────────

  display: screenerMode === 'confluence' ? 'flex' : 'none'
}}>

</div>

This means the component mounts even while Market/Technical/Options/Fundamentals
is active.

Do not do this on initial load.

Implement lazy-first-mount:

    preserve its internal UI state.

first use.

Test Confluence internal filters/state before and after switching away/back.
