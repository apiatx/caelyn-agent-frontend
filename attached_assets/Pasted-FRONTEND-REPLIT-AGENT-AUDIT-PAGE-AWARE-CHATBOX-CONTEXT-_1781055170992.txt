FRONTEND REPLIT AGENT — AUDIT + PAGE-AWARE CHATBOX CONTEXT

You are working in the CaelynAI frontend repo.

Goal:
Make the global popup chatbot page-aware without making it page-limited.

The backend has now fixed the main user-context injection path:

* _user_context survives compression
* chatbox prompt now understands watchlist chunks
* watchlist count/chunks reach Claude
* current page context is additive, not a hard boundary

Now the frontend needs to:

1. send lightweight app/page context with every popup/terminal chat request
2. make popup preset prompt buttons change based on the current page
3. ensure Chart Radar / TradingView pages send ticker/timeframe/chart metadata, not screenshots or raw widget content
4. preserve existing chatbox/terminal paths

Important:
Do not rebuild the chatbox.
Do not move backend investing logic to frontend.
Do not add frontend FMP/Tradier/Hyperliquid calls.
Do not try to scrape/read TradingView widget iframes/canvas.
Do not send huge datasets from frontend.
Backend remains source of truth for watchlist, portfolio, signals, market data, and user account context.

Core behavior rule:
The current page is the user's current focus, not the agent's only context boundary.

Examples:

* If user is on Hyperliquid page and asks about stocks to add to watchlist, the backend should still use watchlist, themes, macro, options, and stock signal context.
* If user is on Watchlist page and asks about crypto/perps, backend can use Hyperliquid context.
* If user is on Chart Radar and asks about a chart, frontend should send selected ticker/timeframe/chart view metadata, while backend should use OHLCV/indicator services for TA.

3. Add lightweight app_context to every chat request
   Every popup and terminal chat request should include:

{
"app_context": {
"route": current pathname,
"page": normalized page name,
"current_focus_page": normalized page name,
"active_tab": active tab if available,
"selected_ticker": selected ticker if available,
"visible_symbols": visible symbols if cheaply available,
"timeframe": selected timeframe if available,
"filters": lightweight filter summary if available,
"sort": lightweight sort summary if available
}
}

Use current_focus_page language.
Do not use names like:

* allowed_context
* current_page_only
* restricted_context
* page_scope_only

Current page should focus the answer, not restrict backend context retrieval.
