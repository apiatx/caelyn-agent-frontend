Backend is already fixed and validated.

Backend now supports:

POST /api/watchlist/earnings/by-symbols

Body:
{
  "symbols": ["AAPL", "MSFT", "NVDA"]
}

Response:
{
  "symbols_requested": [...],
  "events": [...],
  "missing_symbols": [...],
  "source": "cached_earnings",
  "last_updated": "...",
  "stale": false,
  "cache_status": "hit|miss|refreshed|empty"
}

Backend also supports:

GET /api/watchlist/{watchlist_id}/earnings

But preferred frontend path is POST /earnings/by-symbols because Favorites is virtual/global.

Current frontend bug:

Upcoming Earnings is still wrong:
- Primary tab shows earnings from custom watchlist Strong Bases.
- Favorites tab shows no upcoming earnings.
- This means frontend is almost certainly still using old unscoped GET /api/watchlist/earnings, or still reading a stale global earnings response.

Goal:

Replace Upcoming Earnings data source completely.

Upcoming Earnings must use selected symbols from the currently viewed tab and call the backend by-symbols endpoint.

No old global earnings fallback.
