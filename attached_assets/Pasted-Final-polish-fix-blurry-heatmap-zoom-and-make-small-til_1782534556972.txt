Preferred implementation:
Use SVG-native rendering for the heatmap:

* `<svg>` sized to the measured panel
* `<g>` inner layer for zoom/pan
* `<rect>` for tiles
* SVG `<text>` or `<foreignObject>` labels

If using d3.zoom:

* Apply d3 zoom transform to the inner SVG `<g>` for rect positioning.
* Store current zoom transform `k/x/y`.
* Calculate screen-space tile dimensions:
  screenWidth = (x1 - x0) * zoom.k
  screenHeight = (y1 - y0) * zoom.k
* Use these screen-space dimensions to decide which labels to show.

Important anti-blur requirement:
If SVG text inside the zoomed `<g>` appears blurry because the whole group is being scaled, switch to a crisp overlay-label approach:

Option A — preferred for sharp labels:

* Keep tile rects inside zoomed SVG group.
* Render labels in a separate non-scaled SVG overlay layer.
* Convert each tile’s zoomed coordinates to screen coordinates:
  sx = x0 * k + x
  sy = y0 * k + y
  sw = (x1 - x0) * k
  sh = (y1 - y0) * k
* Render `<text>` at sx/sy in the overlay layer.
* Do NOT scale the label group.
* Font sizes remain normal CSS/SVG font sizes, so text stays sharp.
* Labels update on every zoom/pan.

This is how to avoid the “magnifying a bitmap” blur.

Option B:
If labels stay inside the zoomed group, compensate font size by zoom:

* fontSize = desiredScreenFontSize / zoom.k
* strokeWidth = desiredScreenStrokeWidth / zoom.k
  But Option A is cleaner and should be used if blur persists.
