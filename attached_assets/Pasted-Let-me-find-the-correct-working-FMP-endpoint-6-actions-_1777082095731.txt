Holdings service — caching architecture:

The holdings are stored in data/etf_holdings/{symbol}.json on disk so they survive restarts and are never re-fetched unnecessarily. The tiers work as follows:

Age	Behavior
0–7 days	Serve from cache immediately
7–30 days	Serve stale data immediately + trigger background refresh
>30 days	Force live fetch before returning
API fails	Return stale data rather than error
Data source: The correct FMP endpoint turned out to be /stable/etf/holdings (not the legacy /api/v3/etf-holder that was deprecated). Finnhub's holdings endpoint is plan-gated, so it's kept as a fallback for future plan upgrades. No Finnhub calls fire today.

Finnhub usage: Zero additional calls. Quote/history come from the existing Tradier batch + yfinance providers. Holdings only fetch once per 7 days per symbol, only when a popup opens.
