FORMATTING
==========

Opt Score:

* one decimal when needed
* preserve existing score color and signal styling
* do not mix fallback score styling with canonical score styling

IV:

* percentage formatting
* do not multiply values incorrectly; inspect the actual backend unit first

Expected Move:

* use the existing percentage or dollar convention already used by the app
* remain consistent across both pages

Volume and OI:

* compact formatting such as 950, 12.4K, 1.3M

Premium values:

* compact signed currency
* examples: `+$3.2M`, `-$840K`, `$125K`

Net-premium trends:

* signed compact currency
* green for positive
* red for negative
* neutral styling for zero
* em dash only for genuinely unavailable data

Ratios:

* two decimal places
* preserve zero as `0.00`
* do not convert zero to missing

Never use truthiness checks that turn valid numeric zero values into an em dash.
