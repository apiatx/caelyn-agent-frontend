Audit first. Frontend-only unless the required data is missing from the already-loaded Watchlist payload. Do not touch backend. Do not add API/provider calls. Do not use an LLM.

Goal:
On the Watchlist page, rename the top `Tickers` section to:

Screener

Then add a local toggle inside that renamed Screener section:

Technical / Fundamental

The current top `Tickers` table becomes the `Technical` mode.

The existing bottom-tab `Fundamental Screener` table becomes the `Fundamental` mode inside this same renamed Screener section.

In other words:

* Top section title changes from `TICKERS` to `SCREENER`
* Inside that section, user can toggle between:

  * Technical
  * Fundamental

Current behavior:
The top Tickers section currently shows the technical/live ticker table.
The bottom tabs currently include `Fundamental Screener`.

Desired behavior:
The renamed top Screener section owns both:

1. Technical screener
2. Fundamental screener

The bottom `Fundamental Screener` tab should be removed after its content is moved/reused inside the top Screener section.

Do not duplicate the Fundamental Screener in both places.

Scope:
Only update the Watchlist page layout/rendering.

Do not change:

* backend
* data fetching
* provider calls
* Live News
* Golden Zone logic
* Growth Momentum logic
* HC Investment Zone logic
* HC Trade Zone logic
* Fundamental Grouping logic
* Theme Performance logic
* Market Cap Grouping logic
* StockDetailModal

* Hide Foreign behavior, except it should remain available in Technical mode if currently there

Section rename:
Change the top panel header:

`TICKERS`

to:

`SCREENER`

Keep the count text, but update wording if needed:

Example:
`SCREENER 302 total · 248 shown`

Toggle:
Add a compact segmented toggle in the Screener header area:

Technical | Fundamental

Default:

* Technical should be the default mode unless a user has manually switched.
* Optional: persist the selected Screener mode in localStorage.
* Do not interfere with the bottom tab localStorage/default behavior.

Technical mode:

Preserve:

* current columns

* Hide Foreign button

Reuse the existing Fundamental Screener data/helpers/component.

If the current Fundamental Screener is inline inside a bottom-tab render branch, extract it into a reusable component/helper such as:

* `renderFundamentalScreenerTable()`

Fundamental mode should preserve:

* existing Fundamental Screener columns

* existing sorting

* active watchlist filtering
* CSV/fundamental merge logic
* no API calls
* no LLM calls
