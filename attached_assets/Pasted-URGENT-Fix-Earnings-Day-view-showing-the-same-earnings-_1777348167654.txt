Step 2 — Fix query keys
Every Day query key must include selectedDate AND earningsSignalMode.

Use separate keys:

Day Curated:
["earnings", "day", "curated", selectedDate]

Day All:
["earnings", "day", "all", selectedDate]

Do NOT use a generic key like:
["earnings", "day"]
["day-clean"]
["day-curated"]
["earnings", selectedMonth]

Those will reuse stale data across dates.

Step 3 — Fix local cache maps
If there are local refs/maps like:
dayCleanFetchedRef
dayCleanEntries
dayCuratedData
dayCuratedCache
selectedDayEntries

They must be keyed by date.

Bad:
dayCleanEntries = [...]
dayCuratedEntries = [...]

Good:
dayCleanEntriesByDate[dateKey] = [...]
dayCuratedEntriesByDate[dateKey] = [...]

When rendering:
const dateKey = formatDateKey(selectedDate)
const entries =
  earningsSignalMode === "curated"
    ? dayCuratedEntriesByDate[dateKey] ?? []
    : dayCleanEntriesByDate[dateKey] ?? []

Step 4 — Do not render stale previous-day data
When selectedDate changes:
- If new date has cached data, render it immediately.
- If new date has no cached data, show loading/skeleton or empty state for that date.
- Do NOT keep showing previous day’s data as if it belongs to the new day.

If using React Query:
- use isFetching to show subtle loading state
- keepPreviousData is okay only if the UI clearly indicates loading, but better for Day view: do not show previous date’s entries under the new date.

Step 5 — Fix selectedDate update
When user clicks a day cell or day card:
- set selectedDate to that exact date string
- do not derive selectedDate from weekStart/currentMonth incorrectly
- do not mutate Date objects in place

Use immutable date helpers:
const nextDateKey = formatYYYYMMDD(clickedDate)
setSelectedDate(nextDateKey)

Avoid:
selectedDate.setDate(...)
because mutating Date objects can cause React/query cache bugs.
