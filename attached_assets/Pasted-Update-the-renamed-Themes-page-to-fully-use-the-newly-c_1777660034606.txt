Update the renamed Themes page to fully use the newly consolidated backend theme/sector universe.

Context:
Backend has consolidated the old Sectors/Themes data into the canonical Themes by Relative Strength endpoint.

Use this as the single source of truth for the page:

GET /api/themes/relative-strength?timeframe=1D|7D|30D|YTD|1Y&classification=all|sector|theme|sub_theme

Backend now supports:
- classification=sector → 11 SPDR sector rows
- classification=theme → broad/cross-sector theme rows
- classification=sub_theme → narrower sub-theme rows
- classification=all → all rows combined

Old sector/theme endpoints are now compatibility wrappers, but the frontend should prefer the new endpoint directly.

Do not change backend.
Do not change Earnings.
Do not change Options Flow.
Do not change TA Screener.
Do not change Watchlist.
Do not change Portfolio.

Goal:
The Themes page should become one clean market leadership page powered by the canonical backend universe.

2. Default view should be Themes, not Sectors.
3. Existing visual layout should remain mostly the same.
4. Relative Strength and Sector Performance sections should both use /api/themes/relative-strength directly.
5. Remove duplicated theme/sector rendering logic in frontend.
6. Do not hardcode theme lists in frontend.

Classification filter UI:
Replace or adjust the current Sectors/Themes toggle so it reflects the new backend classifications.

Mapping:
- Themes → classification=theme,sub_theme if easy; otherwise classification=all with sector rows filtered out client-side.
- Sectors → classification=sector
- All → classification=all

- Themes mode: /api/themes/relative-strength?...&classification=all, then filter out classification === "sector" in frontend.

Relative Strength section:
Use the selected classification/timeframe data.

Requirements:
- Render every row returned for the selected classification.
- Do not show only gainers.
- Do not hide negative-return rows.
- Do not grey out rows or chips unless the user explicitly deselects them.
- Every chip should have a visible deterministic color.
- Every row should appear in the chart or scrollable chart area.
- Sort by return_pct descending.
- Positive values should extend right.
- Negative values should extend left if the chart supports diverging bars.
- If current chart cannot support left-extending bars, negative rows should still render visibly with a red/negative bar, not disappear.
- Axis/domain must include both positive and negative values:
  min = Math.min(0, lowest return_pct)
  max = Math.max(0, highest return_pct)

Top Leaders / Bottom Laggards cards:
- Top Leaders = top 3 rows by return_pct for selected timeframe/classification.
- Bottom Laggards = bottom 3 rows by return_pct for selected timeframe/classification.
- These cards are summaries only. They should not control which rows appear in the full chart.

- Ticker = proxy_symbols_used[0] if available, else proxy_symbols[0], else theme_id
- Sector/Theme = display_name
- Classification = classification if there is room, or show as a small badge
- Parent Sector = parent_sector if useful, preferably tooltip/detail not a noisy column
- Price = only show if backend provides a reliable price. Do not fake it.
- Selected timeframe return = return_pct
- Score = rs_score
- Trend = keep current sparkline if available; otherwise do not fabricate it
- Status = state

Option A:
Fetch all five timeframes in parallel and merge rows by theme_id so the table can show 1D/7D/30D/YTD/1Y columns.

Option B:
Simplify Themes mode to selected timeframe + score + status.

Prefer Option A if clean and performant. Prefer Option B if safer. Do not show incorrect values.

Duplicate handling:
- Use theme_id as the unique key.
- Do not duplicate rows for the same theme_id.
- If multiple proxies map to one theme, show one row.
- Show proxy_symbols_used in tooltip/detail.

  - Uranium & Nuclear should be one row, not separate URA/URNM/NLR rows.
  - Energy sector and Oil & Gas sub-theme can both exist because one is classification=sector and one is classification=sub_theme.
  - Healthcare sector and Medical Devices/Biotech can both exist because they are different classification levels.
