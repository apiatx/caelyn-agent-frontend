The user should not need to scroll down the page to see the heatmap. The map itself should be a fixed viewport with internal zoom/pan.

   - flex: 1

Treemap sizing logic:
Do not size tiles by raw NET premium only.
Do not size tiles by pure P/C deviation only.

Use a combined conviction/materiality score:

pcr_deviation = abs(log(clamp(premium_pcr, 0.01, 100)))

premium_materiality should be based on real dollar premium, preferably:
gross_premium = call_premium + put_premium

Then create a normalized score within the current view:

materiality_score = normalized/log-scaled gross_premium within current dataset
direction_score = pcr_deviation
tile_size_score = direction_score * materiality_score

Important:
- Extreme P/C with tiny dollar premium should not become a giant tile.
- A $158 premium item with P/C 0.00 should be small.
- A $10M+ premium item far from 1.00 should be large.
- Near-neutral P/C around 1.00 should be small/gray even if total premium is large.
- Use a minimum tile size so tiny names remain hoverable.
- Clamp max score so one extreme item does not eat the whole map.

Suggested implementation:
- safePcr = clamp(premium_pcr ?? 1, 0.01, 100)
- deviation = abs(log(safePcr))
- grossPremium = max(0, call_premium + put_premium)
- materiality = log1p(grossPremium)
- Normalize materiality within the visible dataset.
- sizeScore = max(minSize, deviation * normalizedMateriality)

If the user switches between Sectors, Themes, and All Stocks, recompute normalization separately for that active dataset.

Sorting:
Sort by tile_size_score descending before treemap layout.

Color:
Color direction comes from P/C:
- P/C < 1.00 = green
- P/C > 1.00 = red
- near 1.00 = gray

Color intensity should come from pcr_deviation:
- farther from 1.00 = stronger color
- closer to 1.00 = muted/gray

Neutral band:
0.85 <= P/C <= 1.15 should look gray or almost gray.
