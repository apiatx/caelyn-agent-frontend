PROVEN ISSUE 1 — SORT STILL RERENDERS EVERY ROW
────────────────────────────────────────────────────

Current WlTickerRow props still include:

i: number

and the component uses:

i % 2

for alternating backgrounds/sticky backgrounds.

Therefore sorting changes i for most/all tickers.

Even though the row key is now stable, React.memo sees:

old i != new i

and rerenders most of the ~463 row components.

Fix this.

Remove sort position/index from WlTickerRow props entirely.

Do NOT replace it with another changing parity boolean prop.

Move zebra striping to layout/CSS ownership, for example using stable row
container selectors / nth-child semantics.

Sticky ticker-cell background must remain visually correct.

Required proof:

Sort by Price when 463 rows exist.

A ticker whose stock/state inputs are unchanged must NOT rerender solely because
its sort index changed.

Measure actual renders.

────────────────────────────────────────────────────
PROVEN ISSUE 2 — SHARED rowCtx INVALIDATES ALL ROWS
────────────────────────────────────────────────────

Current WlRowCtx includes mutable whole-page objects such as:

optionsResp
hydrationStatus
localThemeOverrides
themeAssignPendingTicker
themeAssignFeedback

This defeats row isolation.

For example:

one ticker hydration update
→ hydrationStatus Map changes
→ rowCtx changes
→ every WlTickerRow receives new ctx
→ React.memo cannot skip them

Refactor row props into:

A. SHARED STABLE CONTEXT

Only values truly shared across rows and stable during normal updates:

- activeId
- isAdmin
- themeUniverse
- grid/layout config
- stable callbacks
- active screener mode/config

B. ROW-SPECIFIC DYNAMIC PROPS

Resolve at the parent for the specific ticker:

- hydration status for this ticker
- local theme override for this ticker
- theme assignment pending boolean for this ticker
- theme assignment feedback for this ticker
- favorite boolean
- expanded boolean

Do not pass whole Maps merely so each row can call .get(sym).

OPTIONS:

Do not pass the whole optionsResp object to every row.

The merged stock row already owns normalized ticker-level options data.

If the row only needs to know:

loading vs available

pass the minimum stable scalar needed, and only let it change when its visible
meaning actually changes.

Required proof:

One ticker hydration state update must not rerender 462 unrelated ticker rows.

One theme assignment must not rerender 462 unrelated ticker rows.

One new options response must not rerender every Market/Technical row solely
because optionsResp reference changed.
