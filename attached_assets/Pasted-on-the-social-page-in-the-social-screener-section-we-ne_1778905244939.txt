Social Screener — Volume/1d/7d/30d/ytd/1y columns

Root cause: A market-hours guard was blocking data fetches entirely outside NYSE hours (Mon–Fri 9:30–16:00 ET). On a fresh server restart with no cached data, all those columns came back null regardless of time.

Two targeted fixes in social_screener_service.py:

Tradier batch call now always runs — Tradier returns last-trade prices 24/7 (weekends, overnight, holidays). There's no reason to skip it outside hours. This restores volume, current price, and 1d% on any cold start.

FMP stock-price-change now fetches live when cache is cold, even outside hours — This endpoint returns 7d/30d/ytd/1y changes computed from daily closes. It's EOD data that doesn't change intraday, so a Saturday cold-start should get the same numbers as a Tuesday at noon. After first fetch it caches for 30 minutes as before.

Verified result (Saturday cold start): 33/40 volume, 35/40 price changes populated. The 5–7 nulls are OTC/obscure tickers that Tradier simply doesn't cover — that's expected and was happening before too.

Fundamental Screener tab

Turns out it's actually working — 40 rows returned, 33 complete, 3 partial, 4 missing (the 4 missing are the same tiny OTC tickers). The design is already very FMP-friendly: it makes ~50 ticker × 6 endpoint calls on the first cold load, then caches the entire compiled payload for 7 days. Every subsequent visit for a week costs zero FMP calls. I'd recommend keeping it — the API cost is essentially a one-time burst every week, not per-user. The first load after a server restart can take ~8–10 seconds while the background warmup runs, but after that it's instant.
