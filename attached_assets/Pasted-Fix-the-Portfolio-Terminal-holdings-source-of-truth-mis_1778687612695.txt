Fix the Portfolio Terminal holdings source-of-truth mismatch.

Frontend repo:
apiatx/caelyn-agent-frontend

Current bug:
The Portfolio Dashboard and Portfolio Terminal are not showing the same portfolio holdings.

Screenshots:
- Portfolio Dashboard shows the active portfolio holdings entered by the user.
- Portfolio Terminal shows a different/stale set of holdings.
- Some holdings visible in Dashboard are missing from Terminal.
- At least one stale symbol has appeared in Terminal that is not currently in the Dashboard.
- These two views must act as one seamless Portfolio page.

Important:
Do not add new portfolio features right now.
Do not touch Earnings Calendar.
Do not touch FastAPI backend unless absolutely necessary.
This is likely frontend repo / Express routes.ts / Portfolio page hydration.

Goal:
Portfolio Dashboard and Portfolio Terminal must use the exact same active holdings source.

Single source of truth:
GET /api/stock-holdings

The Portfolio Terminal must hydrate from the same holdings data returned by GET /api/stock-holdings, or from the exact same shared readHoldings helper used by GET /api/stock-holdings.

Hard rule:
There should be no separate Terminal-only holdings source.
There should be no legacy/demo holdings file.
There should be no union of multiple holdings files.
There should be no stale cached terminal holdings overriding the active Dashboard portfolio.

Step 3 — Fix /api/caelyn-terminal hydration
In routes.ts, make GET /api/caelyn-terminal use the exact same active holdings source as GET /api/stock-holdings.

Preferred:
- create/reuse one shared helper:
  readActiveStockHoldings()

Then both routes call it:

GET /api/stock-holdings:
  const holdings = readActiveStockHoldings()

GET /api/caelyn-terminal:
  const holdings = readActiveStockHoldings()
  hydrate terminal from holdings

Do not copy/paste two separate readers.
