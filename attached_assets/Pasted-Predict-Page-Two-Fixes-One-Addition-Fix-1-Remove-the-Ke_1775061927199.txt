Predict Page — Two Fixes + One Addition
Fix 1: Remove the Kelly column
The Kelly column always showed "—" because Kelly Criterion only produces a meaningful number when you have an AI-estimated fair value to compare against the market price. Without running the full analysis, it's always zero. Remove the Kelly column entirely from the Intelligence Markets table. Kelly is still present in the deep /analyze response where it actually means something.

Fix 2: Top Edges panel — now populated, update the display
The Top Edges section is now working. The edge signal has changed from the original broken approach to a real one: spread as a percentage of the YES price. A $0.01 spread on a $0.20 market = 5% — that's a real cost/opportunity for anyone transacting.

The top_edges array in /api/predict/signals now returns entries like:

  "edge_pct": 50.0,
  "spread_pct_of_price": 50.0,
  "price_change_1d": 1.5,
  "yes_pct": 6.0,
  "volume_24h": 442562
}
Display for each edge row:

Market question (truncated)
edge_pct formatted as "50.0% spread" — this is the bid-ask width as a fraction of the YES price
yes_pct — current probability
Add a tooltip on the panel header: "Spread as % of YES price — higher = wider bid-ask relative to price, more pricing inefficiency"
Replace the current "No edge data" empty state with: "No edges detected" (it won't be empty anymore but keep the fallback).
